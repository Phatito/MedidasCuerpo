# "Tu semana" — Plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Consumo de kcal editable en el tiempo, estimación del gasto real con kcal recomendadas, e informe semanal con desglose grasa/masa magra, pesadas atípicas, hasta 2 acciones y revisión de la semana pasada.

**Architecture:** Tres módulos puros nuevos en `src/domain/` (`consumo.ts`, `energia.ts`, `semana.ts`), sobre `tendenciaPeso`, `derivar` y `esMenor`. La UI suma un editor de consumo en la tarjeta de peso, una tarjeta "Tu semana" en la ficha y una pantalla `#/p/<id>/semana`.

**Tech Stack:** React 18, TypeScript, Dexie, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-23-tu-semana-design.md` (incluida su sección "Decisiones del constructor").

## Global Constraints

- 7.700 kcal por kg. Rango de consumo 800–6.000. Gasto redondeado a 10; kcal recomendadas a 50; piso 1.200 (mujer) / 1.500 (hombre).
- Ritmo objetivo: `bajar_grasa` −0,5 %/sem, `ganar_musculo` +0,25 %/sem, `mantener` 0. Ritmo siempre sobre la tendencia de los últimos 14 días.
- Ventana de gasto: 28 días (≥ 3 pesadas, ≥ 21 días entre la primera y la última, consumo en ≥ 21 días) → confianza media; 42 días si ≥ 6 pesadas, ≥ 42 días y consumo en ≥ 35 → alta.
- Pesada atípica: |pesada − tendencia anterior| > máx(1 kg, 1,2 % del peso).
- Máximo 2 acciones, en el orden de prioridad del spec. Menores: sin acciones, sin kcal, sin dato de consumo. Datos con más de 28 días: sin acciones ni kcal.
- Todo texto de kcal dice "estimación"/"orientación". Datos inventados en las pruebas. Commits con `Co-Authored-By` y `Claude-Session` de la sesión.

## Review Focus

1. Consumo cambiado a mitad de la ventana (2.500 hasta el 1/11, 2.200 después) → el promedio pondera los días de cada valor (Task 1/2).
2. Persona sin estatura válida o sin % de grasa en ninguna medición → informe sin desglose y sin errores (Task 3).
3. Una sola medición → la tarjeta pide la segunda; dos mediciones el mismo día no rompen el ritmo (Task 3).
4. Respaldo con `consumos` mal formados (fecha inválida, kcal fuera de rango) → se rechaza; respaldo viejo sin el campo → se restaura (Task 1).
5. A 400 px la tarjeta y la pantalla del informe no desbordan (Task 4).

### Task 2: Gasto real y kcal recomendadas (`src/domain/energia.ts`)

**Files:** Create `src/domain/energia.ts`, `tests/domain/energia.test.ts`

**Interfaces — Produces:**
```ts
export type EstimacionGasto =
  | { estado: 'ok'; gastoKcal: number; recomendadaKcal: number; pisoAplicado: boolean; confianza: 'media' | 'alta'; diasVentana: 28 | 42; consumoPromedio: number }
  | { estado: 'faltan'; faltanPesadas: number; faltanDias: number; faltanDiasConsumo: number }
export function ritmoSemanalPct(p: Persona, ms: Medicion[], hasta?: string): number | null  // % de peso por semana, tendencia últimos 14 días
export function estimarGasto(p: Persona, ms: Medicion[]): EstimacionGasto
```
- Cambio de tendencia en la ventana = tendencia en la última pesada − tendencia en la primera pesada de la ventana; días = diferencia entre ambas fechas.

- [ ] **Step 1: Pruebas que fallan** (pesadas semanales inventadas desde 12 semanas antes, bajando 0,5 kg/sem, objetivo `bajar_grasa`, hombre):
  - con 2.500 kcal todo el período → `estado 'ok'`, `gastoKcal` ≈ 3.050 (±60), `confianza 'alta'`, `diasVentana 42`;
  - `recomendadaKcal` = redondeo a 50 de gasto − 0,5 % × peso × 7700/7;
  - con solo 3 pesadas en 21 días y consumo → `'media'`, `diasVentana 28`;
  - con 2 pesadas → `faltan`, `faltanPesadas: 1`; sin consumo → `faltanDiasConsumo: 21`;
  - mujer con gasto 1.300 y objetivo bajar → `recomendadaKcal 1200`, `pisoAplicado true`;
  - consumo que cambia a mitad (Review Focus 1) usa el promedio ponderado;
  - `ritmoSemanalPct` con bajada de 0,5 kg/sem desde 100 kg ≈ −0,5.

### Task 3: Informe semanal (`src/domain/semana.ts`)

**Files:** Create `src/domain/semana.ts`, `tests/domain/semana.test.ts`

**Interfaces — Produces:**
```ts
export type CodigoAccion = 'muy-rapido' | 'proteger-musculo' | 'estancado' | 'reduce' | 'anota-consumo' | 'sigue-anotando' | 'vas-bien'
export interface Accion { codigo: CodigoAccion; texto: string }
export interface Revision { codigo: CodigoAccion; cumplida: boolean; texto: string }
export interface InformeSemanal {
  fecha: string
  anterior: string | null
  cambioTendenciaKg: number | null
  composicion: { grasaKg: number; magraKg: number } | null
  composicionTotal: { desde: string; grasaKg: number; magraKg: number } | null
  barras: { fecha: string; grasaKg: number; magraKg: number }[]
  atipica: { diferenciaKg: number; sentido: 'sobre' | 'bajo' } | null
  gasto: EstimacionGasto | null   // null para menores o datos viejos
  acciones: Accion[]
  revision: Revision[]
  vieja: boolean
}
export function informeSemanal(p: Persona, ms: Medicion[], hoy: string): InformeSemanal | null   // null sin mediciones
```
- Proteína: 1,6–2,2 g por kg del peso de tendencia redondeado a 5 g; con IMC ≥ 30, sobre el peso de IMC 25 a su estatura.
- Revisión: `informeSemanal` con las mediciones hasta `anterior` da las acciones previas; cada una se evalúa con las reglas ✓/✗ del spec.

- [ ] **Step 1: Pruebas que fallan** (datos inventados):
  - desglose: 80 kg / 25 % → 79 kg / 24 % → `composicion { grasaKg: −1,04 (±0,05), magraKg: +0,04 }` y `barras` con 2 elementos;
  - sin % de grasa → `composicion null`, `barras []` (Review Focus 2);
  - pesada 2 kg sobre la tendencia anterior en 80 kg → `atipica { sentido: 'sobre' }`; 0,8 kg → null;
  - ritmo −1,3 %/sem → primera acción `muy-rapido`; masa magra −0,6 kg → `proteger-musculo` con el rango en g; nunca más de 2 acciones;
  - estancado (`bajar_grasa`, ritmo −0,1 %/sem 3 semanas) con consumo y estimación → `estancado` con la kcal recomendada;
  - sin consumo → incluye `anota-consumo`; con consumo pero sin estimación → `sigue-anotando`;
  - consumo actual a ±150 de la recomendada y nada más aplica → `vas-bien` con "sigue con tu consumo actual";
  - menor (nacido en 2015) → `acciones []`, `gasto null`;
  - última medición con 30 días respecto de `hoy` → `vieja true`, `acciones []`;
  - revisión: la semana anterior dio `muy-rapido` y ahora el ritmo es −0,7 %/sem → `cumplida true`;
  - una sola medición → informe con `anterior null` y sin revisión; dos mediciones el mismo día no lanzan (Review Focus 3).
- [ ] **Step 2:** → FAIL. **Step 3:** implementar. **Step 4:** → PASS.
- [ ] **Step 5: Commit** — `feat: weekly report with composition, outliers, actions and review`
